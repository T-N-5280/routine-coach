# Routine Coach（日常打卡助手）

[English](README.md) | 中文（本文件） | [繁體中文](README.zh-TW.md)

一个语音引导、支持中文（大陆／台湾）双版本的日常习惯打卡应用。完全以单个 HTML 文件在浏览器中运行，用自然的语音带你走完早晨和夜晚的日常，并支持跨设备同步。

---

## 这是什么

一个个人习惯辅助应用，具备以下功能：

- 依次引导你完成**早晨**和**夜晚**的日常习惯，配有可视化倒计时圆环
- 每个习惯开始时会**语音播报**（使用 Azure 自然语音，而非浏览器自带的机械音），并每 5 秒用「X分Y秒」的格式语音倒计时
- 支持**引导序列**——一个习惯由多个带计时的子步骤组成（例如拉伸组合：前屈 → 休息 → 横叉 → 休息，重复多次），每个子步骤都可以有自己的语音提示
- 可以为任意习惯设置**特定星期几**才进行（例如洗衣服只在周六）
- 提供完整的**大陆中文／台湾中文**切换——不只是简繁体转换，还包括真实的地区用词差异（如拉伸/伸展、熄灯/關燈等）
- 通过用户自定的「同步码」，借助 Cloudflare KV 实现**跨设备同步**
- 保留**本地版本历史**，带真实的差异对比功能，可以清楚看到任意两个版本之间具体改了什么，并一键恢复到旧版本
- 支持将整套习惯数据**导入／导出**为 JSON，方便备份或批量编辑

---

## 架构

这是一个刻意保持简单的**静态网站 + 一个小型后端代理**架构——没有数据库服务器，没有账号系统，也没有构建步骤。

```
┌─────────────────────────────────────────────────────────────┐
│  你的手机 / 电脑浏览器                                          │
│                                                                 │
│   index.html（整个应用——HTML + CSS + JS，单个文件）            │
│     │                                                          │
│     ├── localStorage ─── 习惯数据、同步码、版本历史、          │
│     │                     语言偏好设置                          │
│     │                     （均按设备本地保存）                   │
│     │                                                          │
│     └── fetch() 请求发往 ↓                                      │
└─────────────────────────────┬───────────────────────────────┘
                               │
                               ▼
                 ┌───────────────────────────┐
                 │  Cloudflare Worker           │
                 │  (tts-proxy)                 │
                 │                              │
                 │  /            → 语音代理      │
                 │  /sync/save   → 写入 KV       │
                 │  /sync/load   → 从 KV 读取     │
                 └───────┬───────────┬──────────┘
                         │           │
                         ▼           ▼
              ┌────────────────┐  ┌─────────────────┐
              │ Azure Speech     │  │ Cloudflare KV     │
              │（自然语音）       │  │（跨设备习惯数据存储）│
              └────────────────┘  └─────────────────┘
```

**为什么需要一个 Worker：** Azure 的语音合成 REST API 不允许浏览器 JavaScript 直接调用（CORS 限制）。这个 Worker 的唯一作用就是充当中间层——它保存真正的 Azure 密钥（浏览器永远看不到），并转发请求。顺便也承担了跨设备同步的后端功能，因为它本来就已经存在。

**为什么没有框架或构建步骤：** 整个项目的初衷就是保持单文件形式，方便随时打开、编辑、重新部署，不需要 npm、打包工具或本地开发服务器。所有的界面、状态管理、渲染逻辑，以及 Azure／同步／历史记录相关的代码，全都写在 `index.html` 的一个 `<script>` 标签里。

## 文件结构

| 文件 | 作用 |
|---|---|
| `index.html` | 整个应用。只有前端代码，没有服务器端逻辑。 |
| `azure-tts-proxy-worker.js` | Cloudflare Worker 源代码。负责代理 Azure 语音请求，并通过 KV 处理跨设备同步。**目前尚未接入自动部署**——详见下方「已知限制」部分。 |

---

## 数据都存在哪里

| 数据 | 存储位置 | 说明 |
|---|---|---|
| 习惯数据（早晨/夜晚日常） | 每台设备的 `localStorage`，如果设置了同步码，也会存入 Cloudflare KV | 本地副本相当于离线缓存；如果启用同步，KV 中的数据才是跨设备的「真正版本」 |
| 语言偏好（大陆/台湾） | 仅存在 `localStorage` | 按设备本地保存，不会同步 |
| 同步码 | 仅存在 `localStorage` | 每台设备各自记住自己连接的是哪个同步码 |
| 版本历史（最近 30 条） | 仅存在 `localStorage` | **不会跨设备同步**——每台设备都有自己独立的历史记录 |
| Azure API 密钥 | Cloudflare Worker 的密钥设置（仅限后台） | 完全不会出现在浏览器或本仓库的任何文件中 |

## 从零开始搭建

### 1. Worker（语音 + 同步后端）

1. 注册一个免费的 Cloudflare 账号。
2. Compute → Workers & Pages → Create Worker，将 `azure-tts-proxy-worker.js` 的内容粘贴进去，点击部署。
3. 在 Settings → Variables and Secrets 中添加：
   - `AZURE_KEY`（你的 Azure 语音资源密钥，需标记为 **Secret**）
   - `AZURE_REGION`（例如 `eastasia`——必须与你 Azure 资源的实际区域一致）
4. 创建一个 KV 命名空间（Storage & Databases → KV → Create namespace）。
5. 将其绑定到 Worker：Settings → Bindings → Add → KV namespace → 变量名**必须精确写成** `ROUTINES_KV`。
6. 记下 Worker 的网址（例如 `https://tts-proxy.你的子域名.workers.dev`）——这个地址需要和 `index.html` 中 `<script>` 顶部的 `PROXY_URL` 常量保持一致。

### 2. 应用本体

两种方式任选其一：

- **直接上传**——Cloudflare Pages → Create → Upload assets → 拖入 `index.html`。以后文件有更新时，需要手动重新上传一次新的部署。
- **Git 自动部署**——Cloudflare Pages/Compute → Create → Connect to Git → 指向本仓库。构建命令留空，输出目录填仓库根目录（`/` 或 `.`）。之后每次 push 都会自动部署。*（本仓库目前具体采用哪种方式，请以 Cloudflare 后台实际显示为准。）*

### 3. 添加到手机主屏幕

在 Safari（iPhone）或 Chrome（Android）中打开应用网址 → 分享/菜单 → 「添加到主屏幕」。这样会得到一个类似原生 App 的图标，打开时没有浏览器地址栏。

## 日常使用说明

- **编辑习惯：** 点击应用底部的「编辑」。修改会自动保存（保存到 `localStorage`，如果已设置同步码，也会同步到云端）。
- **跨设备同步：** 在「跨设备同步」区域输入任意同步码（字母/数字/短横线/下划线，3–64 个字符），点击「设置」完成连接。连接后需要手动选择「从云端拉取」或「推送到云端」——**输入同步码本身不会自动进行任何方向的数据传输**，这是刻意设计，避免数据被静默覆盖。
- **查看历史版本：** 「历史版本」区域会自动记录快照（有修改时大约每 3 分钟记录一次，避免频繁打字时刷屏），可以查看与当前版本的差异对比（用大白话描述改动内容），也可以恢复到任意历史版本。
- **批量编辑／备份：** 「导入 / 导出」区域可以粘贴完整的 JSON 习惯数据（格式见下方），或复制导出当前的数据。

## 习惯数据 JSON 格式（用于导入/导出）

```json
{
  "morning": [
    { "name": "喝水", "seconds": 30, "days": [], "voice": "", "midway": "" },
    {
      "name": "拉伸",
      "days": [1, 3, 5],
      "subSteps": [
        { "name": "前屈", "seconds": 30, "voice": "" },
        { "name": "休息", "seconds": 10, "voice": "" }
      ]
    }
  ],
  "night": []
}
```

- `days`：星期几的数字数组，`0` 表示周日，一直到 `6` 表示周六。空数组 `[]` 表示每天都进行。
- 每个习惯要么是**单一计时**（有 `seconds` 字段），要么是**引导序列**（有 `subSteps` 字段，不带顶层 `seconds`）——两者不会同时存在。
- `voice`：可选，习惯/子步骤开始时播报的自定义语音内容。留空则默认播报习惯名称。
- `midway`：可选，仅对时长超过 40 秒的单一计时习惯生效，在进行到一半时播报的提醒语。

## 已知限制／需要注意的地方

- **Worker 目前没有接入 Git 自动部署。** 更新 `azure-tts-proxy-worker.js` 仍然需要手动把新代码粘贴到 Cloudflare 后台。这是刻意保留的手动步骤，因为让 Worker 自动部署需要在仓库中加入 `wrangler.toml`/`wrangler.jsonc` 配置文件并写明准确的 KV 命名空间 ID，一旦写错就有可能暂时导致语音或同步功能失效——之后有需要可以再着手处理。
- **同步没有真正的身份验证。** 同步码本质上是一个共享密钥，不是登录账号——任何知道你同步码的人都可以通过 Worker 的 `/sync/save` 和 `/sync/load` 接口读取或覆盖你的习惯数据。不要把真正的密码用作同步码，也不要把同步码分享给别人。
- **同步遵循「后写入覆盖」原则，不做智能合并。** 如果两台设备在完全离线的情况下同时修改了同一份数据，最后一个联网同步的设备会覆盖另一台的修改。在正常的个人单人使用场景下，这种情况基本不会遇到。
- **版本历史是每台设备各自本地保存的**，不会通过云端同步。手机上的历史记录和电脑上的历史记录是相互独立的，且都只保留最近 30 条快照。
- **差异对比是按习惯名称匹配的，没有稳定的唯一 ID。** 如果你在改动一个习惯的同时也重命名了它，差异视图会把它显示成「删除了一个习惯 + 新增了另一个习惯」，而不会识别成「重命名」。
- **本应用会在 Azure 请求失败时（离线、超出配额等），自动回退到浏览器自带的 `speechSynthesis` 语音**——所以语音引导理论上不会完全失声，但备用语音听起来会明显更机械化，不如 Azure 自然语音自然。
